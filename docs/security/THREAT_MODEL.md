# Threat model: cerbo-supplement-store

This page lists who could attack the app, what they would try, what stops them, and which test proves it.
Every defence points at a file and line. Every proof points at an acceptance test (AT id) or, where no AT
exists, a unit test. A row with no test says "⚠ no test". Anything the repo does not contain says "⚠ not built".
People in the examples are the synthetic demo users (Ana and Ben are patients, Dr. Chen and Dr. Lee are
providers, Omar, Fran, Dana and Sam are operations staff; all on example.test).

## Trust boundaries

From `docs/architecture/hld.md` §5 (TB-1 to TB-5).

| Id | Boundary | Less trusted side | What guards the crossing |
|---|---|---|---|
| TB-1 | Internet → web app | any browser, signed in or not | session check `requireViewer` (`server/services/session.ts:204`), security headers (`nuxt.config.ts:13`), JSON-only bodies (`server/utils/problem.ts:50`) |
| TB-2 | Between roles inside the app | a signed-in person of one role | BE-4 AccessPolicy, one place, deny by default (`server/services/access-policy.ts:16`) |
| TB-3 | Web app → database | app code, which can have bugs | the app's database user `supplements_app` gets narrow grants; CHECK constraints and triggers guard money (`db/migrations/1760000002000_payments-ledger.sql:6`, :17, :76, :104) |
| TB-4 | Web app → outside providers | payment and messaging providers (stubs today) | in-process stubs (`server/services/payment-gateway.ts:34`, `server/services/messaging.ts:15`) |
| TB-5 | Host platform → our system | the host account and its secret store | outside the repo: ⚠ not built here (CHECKLIST N3) |

## Gaps, ranked (⚠ rows)

Worst first. "Not built" means the repo has no defence; "no test" means the defence exists but nothing proves it.

1. **T-28 embed identity (not built).** No launch-token check exists. Harmless today because framing is blocked
   (`nuxt.config.ts:21`). It becomes the main trust boundary the day the app is embedded in Cerbo (N7).
2. **T-27 host and secrets (not built, no test).** Secret store, private database network, database TLS and
   host two-factor live outside the repo (N3, N6). No verified history scan has run (N4).
3. **T-26 real payment provider (not built, no test).** Signature verification and confirm-by-asking do not
   exist yet. Must ship with the first real provider, together with the D49 trigger for node-forge.
4. ~~T-13, T-5, T-16~~ closed in M7.1: M7.1_AT_002, M7.1_AT_001 and M7.1_AT_003 (with BE-23 OriginGuard, D91).
7. **T-17 clickjacking (no AT).** Header is unit-tested from config only; the live header is unchecked (N1).
8. **T-24 open redirect (no AT).** `safeNext` is unit-tested only.

Medium residual risks with tests in place: T-9 and T-11 (owner role and live grants unchecked, N10),
T-15 (shared demo password, Q2; proxy address, N2), T-25 (read routes unlimited, SEC-17).
