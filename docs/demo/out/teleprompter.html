1. 0:00The GitLab repo

    This is a supplement ordering service built for Cerbo, an EHR used by functional-medicine practices.

  2. 0:07Dr. Chen builds Ana's order

    A provider builds an order for a patient. As items are added, it shows the total, the 0.75% platform fee, and the provider's payout. Then the provider sends it.

  3. 0:20Ana opens her order and pays

    The patient signs in, opens the order, and pays. Payment is idempotent: pressing pay twice still charges once. The receipt lists each item and the total.

  4. 0:34Fran's financial report

    Finance sees each month split into cost, payouts and fees, and whether it balances.

  5. 0:42High-level design diagrams

    The architecture is one Nuxt app and one PostgreSQL database. Payments and messaging are stand-ins behind their own interfaces, so real providers can replace them later.

  6. 0:54Data model, then the pay sequence

    Every payment is recorded on the order and in an append-only ledger that must balance. A repeated payment request returns the stored response instead of charging again.

  7. 1:08My answers in the product spec

    AI wrote most of this code under my review, and I corrected it where it was wrong. It treated a competitor's discount cap as a price ceiling, and it wanted to defer the order dashboard. I changed both.

  8. 1:26The decision ledger

    Every decision is recorded, grouped here by topic, with the options we rejected.

  9. 1:32The planted-bug check

    We also plant bugs in the money code on purpose, to prove the tests catch them.

  10. 1:38The top of payments.ts

    Payment uses two short transactions around the charge, so no lock is held while waiting.

  11. 1:45The reviewer guide
