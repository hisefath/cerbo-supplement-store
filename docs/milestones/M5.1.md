## 12. Rollback

- Merge method: merge (one merge commit).
- One command, after the merge:
  `m=$(git log main --first-parent --merges -1 --format=%H --grep="milestone/m5.1-visual-refresh"); [ -n "$m" ] && git revert -m 1 "$m" || echo "no merge of milestone/m5.1-visual-refresh on main yet"`
- Why one revert is enough: the merge commit has two parents, main as it was (parent 1) and this branch (parent 2). `-m 1` undoes exactly what the merge added on top of parent 1, which is this milestone's work. The merge inside the branch (1, `0fd7dc5`, the M5 ship records, information only) is not a sync from main. A revert would also take back those M5 record lines in MILESTONES.md and deploy.md (DV-5).
- Data, migrations, config a revert does not undo: no migration and no config change. `db/seed/demo.ts` (RESET_TABLES) and `tests/unit/seed-demo.test.ts` are code that the revert itself restores. The font dependencies in `package.json`/`package-lock.json` revert with the code; after a revert, `make setup` (npm ci, AGENTS.md) reinstalls the old set.
