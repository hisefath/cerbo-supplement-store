Close the milestone review's findings that change behaviour: cancel never races a payment, signing in from a "signed out" message returns the person to their page, and a below-floor refusal names every item.

- FR-067: "If a provider tries to cancel an order whose checkout has started or that is paid, then the system shall refuse and leave the order unchanged."
- FR-004: "If an order's provider payout after the platform fee would be below $0.00, then the system shall refuse to send it and name the items priced below their floor."

- Fix 1 (finding R2, P1): `cancelOrder` in server/services/orders.ts also cancels an `in_checkout` order whose hold has ended (`eb.and([eb('status', '=', 'in_checkout'), eb('prices_held_until', '<=', …)])`). A payment can be in flight while the hold ends: the charge succeeds, the cancel wins, and recording the payment then fails, so a charged order ends cancelled with no ledger lines. Allow cancel only from `sent` and `payment_failed`, exactly as SM-1 and M4-T008's Must-not-change line say.
- Fix 2 (finding R3, P2): the "Sign in" link that app/components/ProblemMessage.vue shows for `unauthenticated` goes to `/sign-in` with no `next=`, so the person loses the page they were on (screens.md S2: "Sign in to return to your order."). Carry the current path as `next` (the sign-in page already accepts only same-site paths).
- Fix 3 (finding R4, P2): the S1 `below-price-floor` message names only `productIds[0]`. Name every product in `productIds` (FR-004 "name the items"). Keep the screens.md S1 wording for the one-product case.
- Fix 4 (finding R1, P3): tests/unit/money.test.ts "… names every product" uses one product, so it cannot catch a bug that names only the first; give it at least two products.
- Fix 5 (finding R15, P3): the Makefile comment on `test-acceptance` still says the suite is "not part of check until merge"; `check` now runs it and needs `make db-test-up`. Correct the comment only; change no recipe.
