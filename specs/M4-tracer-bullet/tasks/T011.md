## Ask

Security hardening before G5

Close the six security findings the human chose to fix at G5 (docs/security/CHECKLIST.md SEC-4, SEC-6, SEC-7, SEC-8, SEC-9, SEC-11; Approvals 2026-10-10 "Approve, add T011 and run it").

- Slice: seam — app-wide response headers (nuxt.config.ts route rules), BE-3 session lifetime, BE-1 error logging, BE-10 pay rate limit (EP-23), sign-in attempt retention
- FR-006: "When a patient confirms payment for an order in checkout, the system shall mark the order paid and show the patient a receipt with the amount paid."
- FR-041: "When a signed-in person has been inactive for 15 minutes, the system shall sign them out and show the sign-in page."
- NFR-010: "The system's logs hold 0 records containing a patient's name, an order's items or payment details."
- Fix 1 (SEC-4): send security headers on every response: a Content-Security-Policy that includes `frame-ancestors 'self'` (scripts and styles from the app's own origin; allow what the built Nuxt app needs and nothing more), `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, and `Strict-Transport-Security: max-age=31536000; includeSubDomains`. Configure them once (Nuxt `routeRules` or a Nitro middleware under Owns), not per route.
- Fix 2 (SEC-8): order, session and operations responses (`/api/**` and the S2, S3, S4 pages) send `Cache-Control: no-store`.
- Fix 3 (SEC-6): an absolute session lifetime of 12 hours from sign-in, on top of the 15-minute idle limit: a session older than 12 hours answers 401 `/problems/unauthenticated` and is ended, however active it is. Use the session's existing created time; no schema change.
- Fix 4 (SEC-7): no log line may carry an error object or a database row. The unexpected-error log (server/utils/problem.ts) and the two payment logs (server/services/payments.ts, server/services/payment-gateway.ts) write only the instance id, the error class name, a PostgreSQL error code and constraint name when present, never `err` itself or its message (a constraint error message holds the failing row's amounts).
- Fix 5 (SEC-9): rate-limit EP-23 the same way as sign-in (the human approved "same pattern as the sign-in limit"): more than 10 payment attempts in 15 minutes for one person or one address answers 429 `/problems/rate-limited` with `retryAfterSeconds`, safe under parallel requests (lock, then count and record, in one transaction), keeping the address rule of `clientAddress` in server/services/session.ts. Record attempts in a table this task's migration creates; the acceptance helpers empty every table before each test. A replay of a stored idempotent response does not count as a new attempt.
- Fix 6 (SEC-11): old rows in `sign_in_attempts` (and the new pay-attempt table) are deleted on a schedule even when nobody signs in: a Nitro scheduled task under `server/tasks/` that runs at least hourly and deletes rows older than 15 minutes (enable Nitro scheduled tasks in nuxt.config.ts).
- Out of this task: CSRF tokens (SEC-5, accepted as D52); a quantity cap (SEC-10, accepted as D53); the dependency advisories (SEC-1 to SEC-3, accepted as D49 to D51); the proxy address setting `TRUST_PROXY=1` on Railway (ship-milestone).
